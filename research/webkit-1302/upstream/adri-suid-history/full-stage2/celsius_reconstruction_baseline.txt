65:## Celsius (ffs_mount) Technical Analysis
66-
67:The vulnerability is in `ffs_mountfs()` in `sys/ufs/ffs/ffs_vfsops.c`:
68-
69-```c
70-size = fs->fs_cssize;                          // attacker controlled
71-if (fs->fs_contigsumsize > 0)
72-    size += fs->fs_ncg * sizeof(int32_t);      // INTEGER OVERFLOW
73-size += fs->fs_ncg * sizeof(u_int8_t);         // INTEGER OVERFLOW
74:space = malloc((u_long)size, M_UFSMNT, M_WAITOK);  // small malloc
75-
76-// Later:
77-for (i = 0; i < fs->fs_ncg; i++)               // huge loop
78-    *lp++ = fs->fs_contigsumsize;               // HEAP OVERFLOW
79-```
80-
81:`fs->fs_ncg` comes from the UFS superblock (attacker controlled). A large value causes integer overflow in the size calculation, resulting in a small malloc but massive heap overflow.
82-
83:**Requirements:** BD-J or Vue entry point + 250GB+ HDD with malformed UFS image.

29:## Celsius / ffs_mount — Integer Overflow 🔥 CONFIRMED
30-
31-- **Type:** Kernel heap overflow
32:- **Component:** ffs_mountfs() in sys/ufs/ffs/ffs_vfsops.c
33-- **Discovered by:** bollars (via kernel diffing)
34-- **Works on:** PS4 up to 13.04, PS5 up to 12.70
35-- **Patched in:** PS4 13.50, PS5 13.00
36-- **Status:** CONFIRMED — vulnerable code present in FreeBSD 9
37-
38-### Vulnerable code:
39-```c
40-// Line ~910 in ffs_vfsops.c
41:size = fs->fs_cssize;                          // from superblock (attacker controlled)
42-blks = howmany(size, fs->fs_fsize);
43:if (fs->fs_contigsumsize > 0)
44:    size += fs->fs_ncg * sizeof(int32_t);      // INTEGER OVERFLOW HERE
45:size += fs->fs_ncg * sizeof(u_int8_t);
46:space = malloc((u_long)size, M_UFSMNT, M_WAITOK);  // allocates SMALL buffer
47-
48-// Later in the same function:
49:if (fs->fs_contigsumsize > 0) {
50-    fs->fs_maxcluster = lp = space;
51:    for (i = 0; i < fs->fs_ncg; i++)           // iterates fs_ncg times
52:        *lp++ = fs->fs_contigsumsize;           // HEAP OVERFLOW
53-    space = lp;
54-}
55-```
56-
57-### Exploitation:
58:1. Craft UFS image with malicious superblock (fs_ncg = 0x40000001)
59:2. Mount via BD-J or Vue entry point
60-3. Integer overflow causes small malloc + massive heap write
61-4. Heap grooming needed to control what gets overwritten
62-5. Convert heap overflow to kernel read/write
63-6. Patch kernel, load payload
64-
65-### Requirements:
66:- BD-J or Vue userland entry point
67:- 250GB+ HDD with malformed UFS image (per Victor's guidance)
