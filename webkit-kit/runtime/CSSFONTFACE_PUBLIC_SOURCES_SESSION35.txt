The public README at commit 221baa6e7349b96a6fd299808a25a4178e47741c states: vulnerability scope PS4 6.00-13.52, but exploitable-in PS4 only 6.00-11.02; PS5 scope 1.00-13.40, exploitable-in 1.00-8.60. The public write-up by Nathan Fargo and ufm42 (June 24, 2026) attributes the root lifetime issue to CSSFontFaceSet::matchingFacesExcludingPreinstalledFonts returning `Vector<std::reference_wrapper<CSSFontFace>>`, consumed by FontFaceSet::load(). The described fix changes the return type to `Vector<Ref<CSSFontFace>>`, holding strong references while load completes. It identifies re-entry through FontFace::fontStateChanged() resolving a loaded promise, and stylesheet mutation removing CSS-backed faces. This is public write-up evidence; it is not a retail 13.52 byte-level proof.

The same write-up states the UAF is only an initial trigger and that a later controlled state is needed for memory disclosure/read/write; it does not make 13.52 exploitable. It reports disabled/modified WebKit features on PlayStation and discusses allocator/layout differences. Operational exploitation details are intentionally not reproduced here.

Current upstream WebKit source evidence:

- https://github.com/WebKit/WebKit/blob/main/Source/WebCore/css/CSSFontFace.h: current CSSFontFace is `RefCountedAndCanMakeWeakPtr<CSSFontFace>`, has `Ref<CSSFontFace> create`, `Ref<FontFace> wrapper`, `FontFace* existingWrapper`, `WeakHashSet<CSSFontFaceClient> m_clients`, `WeakPtr<FontFace> m_wrapper`, `Timer m_timeoutTimer`, and private `const Variant<Ref<MutableStyleProperties>, Ref<StyleRuleFontFace>> m_propertiesOrCSSConnection` before `m_family`, `m_ranges`, `m_featureSettings`. This confirms the modern layout shape, not PS4 13.52.
- https://github.com/WebKit/WebKit/blob/main/Source/WebCore/css/CSSFontFaceSet.cpp: current `m_faces` and lookup tables use `Vector<Ref<CSSFontFace>>`; `remove(const CSSFontFace&)` locally protects the face; `add()` appends strong refs; the source is a modern upstream reference.
- https://github.com/WebKit/WebKit/blob/main/Source/WebCore/css/FontFaceSet.cpp: current `load()` obtains matching faces, then iterates `for (Ref face : matchingFaces) face->load();`, retains `Ref` while checking status and appending wrappers, and uses pending promises. This is a modern ownership model and cannot be assumed to match PS4 13.52.
- https://bugs.webkit.org/show_bug.cgi?id=164902: separate 2016 FontFaceSet.load promise bug, fixed as WebKit r208889 on 2016-11-18; classify historical-only and do not conflate with CSSFontFace UAF write-up.
